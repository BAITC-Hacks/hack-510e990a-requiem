# EventMatch — объяснимый подбор подрядчиков

MVP для HackAlem, задача #79-lite. Принимает город, дату, формат мероприятия, категорию и бюджет, возвращает до трёх подходящих подрядчиков. Дополнительно учитывает язык и длительность. Каждая карточка объясняет соответствие условиям и приводит характерный фрагмент исходного описания.

## Запуск за две минуты

Нужен Node.js 22.12 или новее и npm. Команды выполняются из папки проекта.

```sh
npm ci
npm start
```

Открыть http://127.0.0.1:3000. Без ключа AI приложение полностью выполняет подбор и честно помечает объяснения как составленные по каталогу. Интернет нужен для первой установки зависимостей; после установки базовый режим работает локально без интернета.

Для автоматического перезапуска сервера при редактировании: `npm run dev`. Для проверки: `npm test` или `npm run check` (синтаксис и тесты).

Если порт занят, укажите другой `PORT` в `.env`. Для демонстрации в локальной сети можно указать `HOST=0.0.0.0`. По умолчанию сервер доступен только с этой машины. В публичный интернет приложение автоматически не публикуется.

## Подключение AI

1. Скопируйте `.env.example` в `.env`.
2. Локально задайте `OPENAI_API_KEY` и доступную вашему аккаунту модель в `OPENAI_MODEL`. Пример настройки — `gpt-4o-mini`, поддерживающий структурированный вывод. Доступность конкретной модели и квота зависят от аккаунта.
3. Перезапустите сервер. Выполните запрос. Под карточками должно появиться «AI выбрал особенности из описаний».

Ключ не помещается в браузер, исходники или Git. Файл `.env` исключён из Git. Не пересылайте ключ в переписке. Использование API может расходовать баланс аккаунта.

AI вызывается одним запросом для максимум трёх уже выбранных профилей. Вызов использует OpenAI Responses API и строгую JSON Schema; модель возвращает только ID профиля и ID одного исходного фрагмента. Сервер проверяет существование каждой пары и полноту ответа. Цена, язык, доступность и порядок карточек определяются сервером, не моделью. Текст описаний рассматривается как данные, а не инструкции.

### AI-ассистент поиска

Над формой доступно поле для запроса обычным языком. Например: «Нужен ведущий в Алматы на корпоратив 10 октября 2026 года, до 1,5 млн тенге, на русском». Ассистент:

- преобразует только явно названные условия в структурированные изменения;
- показывает распознанные значения в обычной форме;
- просит уточнить обязательные поля, которые не были указаны;
- понимает точечные изменения вроде «А на 11 октября?»;
- запускает тот же проверяемый подбор, что и ручная форма;
- при пустой выдаче предлагает ближайшую подходящую дату и минимальный рабочий бюджет, только после повторной проверки каталога;
- сравнивает показанные карточки по цене, языкам и длительности без заявлений о качестве.

Новый запрос не наследует демонстрационные значения. Старый ответ ассистента игнорируется, если пользователь успел изменить форму. Модель не получает полный CSV и не выбирает подрядчиков: она видит сообщение, текущий черновик и допустимые значения справочников. Все динамические факты вычисляет сервер.

Проверить ключ без его вывода: `npm run check:ai-key`. Выполнить сквозной запрос через ассистента: `npm run check:ai`. Обе команды обращаются к OpenAI API и могут расходовать небольшой объём баланса.

Документация: https://developers.openai.com/api/docs/guides/structured-outputs

Лимит ожидания AI по умолчанию 5 секунд; допустимая серверная настройка ограничена 0,5–7 секундами. При ошибке, отказе, таймауте или некорректном ID приложение возвращает фактические объяснения и явно сообщает о резервном режиме. Для пустого результата AI не вызывается. Успешные объяснения кешируются в памяти (до 200 запросов); кеш сбрасывается при перезапуске.

**Ограничение проверки:** автоматические тесты проверяют контракт AI на имитированных ответах, включая отказ, выдуманные ID и таймаут. Успешный реальный вызов OpenAI требует вашего ключа и отдельной проверки после настройки. Подключённый ключ сам по себе не доказывает успешность AI-вызова: смотрите режим под карточками.

## Данные

`data/contractors.csv` — неизменённый CSV организаторов: 66 уникальных профилей, 17 категорий, 3 значения города. 13 профилей синтетические, у 18 проставлена цена, у 8 — город. Все эти флаги сохранены и отображаются в карточках. Дополнительные профили не создавались.

Массивы в CSV разделены `|`; `csv-parse` разбирает внешнюю структуру с кавычками и запятыми. Числа и Boolean преобразуются при запуске. `max_hours` пуст у 9 профилей: это «неприменимо», а не 0. Для них проверка часов пропускается, но занятость по датам действует. Некорректный каталог приводит к отказу запуска с указанием поля и строки.

Календарь: **23 сентября — 31 декабря 2026 включительно**. Даты вне окна отклоняются, поскольку отсутствие записи не доказывает доступность вне известного периода. Календарные даты сравниваются как `YYYY-MM-DD` без локальных часовых сдвигов.

Цены указаны «от» за мероприятие, не за час и не за гостя. Проверяется только начальная цена. Итоговая смета, качество работы, реальные отзывы и подтверждение бронирования отсутствуют. Описания — заявления самих подрядчиков, не независимо проверенные факты. Структурированные поля имеют приоритет над описаниями при фильтрации.

## Алгоритм

1. Проверка входных полей и календарного окна.
2. Город + принадлежность категории массиву `categories`.
3. Исключение занятых на дату.
4. Начальная цена не превышает бюджет.
5. Формат входит в `event_formats`.
6. Если задан язык — он входит в `languages`.
7. Если задана длительность и `max_hours` не `null` — запрошенная длительность не больше `max_hours`.
8. Сортировка по начальной цене, затем по ASCII-идентификатору; максимум 3 карточки.
9. Проверенные условия + фрагмент описания образуют объяснение.

Это прозрачная экономическая сортировка среди допустимых кандидатов, **не рейтинг качества**. AI не ранжирует кандидатов. Повторяемость порядка обеспечивается алгоритмом и версией датасета, а не настройкой температуры модели.

Для сводки каждый исключённый профиль относится к первой нарушенной проверке в указанном порядке. Поэтому `in_category = eligible + sum(excluded)`. Причины могут пересекаться в реальности, но счётчики не дублируют людей. Отдельно можно раскрыть имена занятых; они не попадают в карточки рекомендаций. После смены только даты интерфейс называет ранее выбранных подрядчиков, занятых на новой дате.

Три бизнес-исхода:

- `matched`: найден хотя бы один кандидат; 1–2 результата не дополняются неподходящими.
- `category_absent`: в выбранном городе категории нет.
- `no_matches`: категория есть, но никто не прошёл условия.

Ошибки ввода, связи и сервера показываются отдельно и не выдаются за отсутствие кандидатов.

## Архитектура

```text
Браузер (HTML/CSS/JS)
        ↓ POST /api/recommend или /api/assistant
Express → AI разбирает изменения → проверка ввода → фильтры → стабильная сортировка
        ↑ CSV в памяти                   ↓ максимум 3
                           AI выбирает фрагменты / fallback
                                        ↓
                         проверка фрагментов → карточки
```

Один процесс Node.js, два npm-пакета: Express 5 и csv-parse 6. Нет сборщика, базы данных, регистрации, платежей, внешних шрифтов или изображений. Один сервер обслуживает страницу и API; настройка CORS не требуется. Все динамические тексты в браузере вставляются через `textContent`, а не HTML. Выдаётся Content Security Policy. Размер JSON-запроса ограничен 8 KB. Статика ограничена папкой `public`, CSV и серверные файлы через HTTP не раздаются.

Это локальный хакатонный MVP. Перед публичной эксплуатацией нужны ограничение частоты запросов и бюджета AI, защита от массовых параллельных вызовов, мониторинг и актуальные календари. У приложения нет бронирований или уведомлений.

| Ответственный | Файлы | Ветка |
|---|---|---|
| Frontend | `public/` | `frontend` |
| Backend и AI | `server/`, `tests/`, зависимости и контракт API | `backend` |
| Интегратор | Проверка PR, запуск, документация и демонстрация | `main` для проверки; правки документации — отдельным PR |

Контракт API: [docs/api-contract.md](docs/api-contract.md). Сценарий защиты и ожидаемые результаты: [docs/demo-scenarios.md](docs/demo-scenarios.md).

Подробная инструкция по выбору ветки, распределению файлов и объединению изменений: [TEAM.md](../TEAM.md). В обеих рабочих ветках находится весь проект. Согласуйте изменения контракта до правки UI. Общие зависимости меняет backend-разработчик по согласованию с командой. Перед PR: `npm run check`. Проверяющий запускает проект после `npm ci`, а не использует чужую папку `node_modules`. Ключи и `node_modules` не коммитятся. Зависимости зафиксированы в `package-lock.json`.

## Что дальше
